# 新機能「自動レポート生成」リリース振り返り

著者: 鈴木花子 / 提出先: プロダクト・開発合同レビュー会 / 日付: 2025-09-30 / 想定: 20分 + 質疑10分

## サマリー

2025年6月15日にリリースした新機能「自動レポート生成」は、リリース後3ヶ月で予想を大きく上回る採用率を達成した。エンタープライズ顧客の62%が少なくとも1回使用し、月次アクティブ利用率は45%に到達。レポート作成時間が平均で1/8に短縮されたという顧客フィードバックも複数得られている。一方、リリース後にパフォーマンス問題が2回発生し、運用チームの負担が増加した点は今後の課題として残った。

## 採用状況

リリース直後の採用は緩やかだったが、7月の機能改善と8月のドキュメント刷新を経て、加速度的に伸びた。9月末時点で、エンタープライズの62%が機能を利用、ミッドマーケットは34%、SMBは18%となっており、セグメントごとに採用速度の差が明確に出ている。SMBの低さは機能の複雑度が要因と分析している。

| 顧客セグメント   | 採用率 | 月次アクティブ率 |
|------------------|-------:|----------------:|
| エンタープライズ |  62%   |  45%            |
| ミッドマーケット |  34%   |  21%            |
| SMB              |  18%   |   9%            |

(データ元: ./data/feature_adoption.xlsx, シート: 採用率Q3)

## ユーザーからのフィードバック

NPS調査では、本機能利用ユーザーのNPSスコアは+38を記録(全機能平均は+22)。定性的なフィードバックでは「レポート作成時間が週8時間から週1時間に削減できた」という肯定的な声が多い一方、「カスタマイズ性が物足りない」という指摘も約20%のユーザーから出ている。

(データ元: ./data/feature_nps_survey.xlsx, シート: 自動レポート機能)

## 課題と次期対応

リリース後に発覚した主な課題は以下の通り。特にパフォーマンス問題は2回の障害を引き起こし、運用チームに大きな負担をかけた。これらは現在は解消済みだが、根本的な改善のため、次期バージョンでのアーキテクチャ見直しを計画している。

| 課題                       | 影響度 | 対応状況 |
|----------------------------|:------:|:--------:|
| 大規模データでの遅延       |   高   | 完了     |
| メモリ使用量の想定外増加   |   中   | 対応中   |
| カスタマイズ性不足の指摘   |   中   | 計画中   |
| 細かなUI不具合 (15件)      |   低   | 順次対応 |

(データ元: ./data/post_release_issues.xlsx, シート: Q3課題一覧)

## チームの貢献

本リリースは開発・QA・ドキュメント・カスタマーサクセスの連携で実現した。特に8月のドキュメント刷新を主導したテクニカルライターチームの貢献が、採用率急上昇のターニングポイントとなった。

![リリース当日のチーム写真](./images/launch_team.jpg)

## まとめと次期計画

「自動レポート生成」のリリースは、2025年最大の成功事例の一つとなった。次期リリースでは、本機能のカスタマイズ性向上と、パフォーマンス改善版アーキテクチャ移行を最優先で進める方針。

## 想定質疑

- SMB採用率の低さ → 機能の複雑度が要因。SMB向け簡易版を検討中
- パフォーマンス問題の根本原因 → アーキテクチャ設計時の想定見積もり不足
- カスタマイズ性向上の優先度 → Q4で要件定義、Q1リリース予定
